### 2.1 策略模式：题库解析器（Parser）

**问题**：用户可能上传 TXT、MD、Word、PDF 等不同格式，每种格式解析规则不同。

```javascript
// 策略接口
class ParserStrategy {
  parse(fileContent) {
    throw new Error('子类必须实现 parse 方法');
  }
}

// TXT 解析策略
class TxtParser extends ParserStrategy {
  parse(content) {
    // TXT 解析逻辑
    return this.parseTxt(content);
  }
  
  parseTxt(content) {
    const questions = [];
    // 具体实现...
    return { name: '题库', questions };
  }
}

// MD 解析策略（继承 TXT，只做微调）
class MdParser extends TxtParser {
  parse(content) {
    // MD 格式略有不同，但大部分逻辑一致
    const preprocessed = content.replace(/^#+\s+/gm, '## 题目');
    return super.parse(preprocessed);
  }
}

// Word 解析策略
class WordParser extends ParserStrategy {
  async parse(file) {
    // 需要 mammoth 库
    const result = await mammoth.extractRawText({ arrayBuffer: await file.arrayBuffer() });
    const txtParser = new TxtParser();
    return txtParser.parse(result.value);
  }
}

// 使用
class ParserContext {
  setStrategy(strategy) {
    this.strategy = strategy;
  }
  
  async parse(input) {
    return this.strategy.parse(input);
  }
}

// 对外暴露的简单接口
async function parseFile(file) {
  const context = new ParserContext();
  
  if (file.name.endsWith('.txt')) {
    context.setStrategy(new TxtParser());
  } else if (file.name.endsWith('.md')) {
    context.setStrategy(new MdParser());
  } else if (file.name.endsWith('.docx')) {
    context.setStrategy(new WordParser());
  } else {
    throw new Error('不支持的格式');
  }
  
  const content = await file.text();
  return context.parse(content);
}
```

**为什么用策略模式？**
- 新增格式（如 PDF）只需新增一个类，不改原有代码
- 符合开闭原则（对扩展开放，对修改关闭）
- 每种格式的解析逻辑独立，易于测试

### 2.2 策略模式：计分器（Scorer）

**问题**：考试型、游戏型等不同计分方式，未来可能还有更多。

```javascript
// 计分策略接口
class ScoringStrategy {
  calculate(answers, questions) {
    throw new Error('子类必须实现 calculate');
  }
  
  getResultType() {
    return 'base';
  }
}

// 考试型计分
class ExamScoring extends ScoringStrategy {
  calculate(answers, questions) {
    let correctCount = 0;
    for (let i = 0; i < questions.length; i++) {
      if (answers[i] === questions[i].correct) {
        correctCount++;
      }
    }
    const score = Math.round((correctCount / questions.length) * 100);
    
    return {
      type: 'exam',
      score,                    // 百分制 0-100
      correctCount,
      total: questions.length,
      maxScore: 100
    };
  }
}

// 游戏型计分
class GameScoring extends ScoringStrategy {
  constructor(config = {}) {
    super();
    this.baseScore = config.baseScore || 10;
    this.streakBonus = config.streakBonus || 5;
  }
  
  calculate(answers, questions) {
    let totalScore = 0;
    let streak = 0;
    let maxStreak = 0;
    
    for (let i = 0; i < questions.length; i++) {
      const isCorrect = answers[i] === questions[i].correct;
      
      if (isCorrect) {
        streak++;
        maxStreak = Math.max(maxStreak, streak);
        let questionScore = this.baseScore;
        
        if (streak >= 3) {
          questionScore += this.streakBonus * Math.floor(streak / 3);
        }
        totalScore += questionScore;
      } else {
        streak = 0;
      }
    }
    
    return {
      type: 'game',
      score: totalScore,        // 经验值
      maxStreak,
      correctCount: answers.filter((a, i) => a === questions[i].correct).length,
      total: questions.length
    };
  }
}

// 使用
class ScoringContext {
  setStrategy(strategy) {
    this.strategy = strategy;
  }
  
  calculateScore(answers, questions) {
    return this.strategy.calculate(answers, questions);
  }
}

// React Hook 中使用
function useScoring(scoringMode, gameConfig) {
  const context = new ScoringContext();
  
  if (scoringMode === 'exam') {
    context.setStrategy(new ExamScoring());
  } else {
    context.setStrategy(new GameScoring(gameConfig));
  }
  
  return (answers, questions) => context.calculateScore(answers, questions);
}
```

### 2.3 状态模式：答题流程（QuizState）

**问题**：答题有多个阶段（未开始、答题中、即时反馈、考试模式、已完成），不同阶段行为不同。

```javascript
// 状态接口
class QuizState {
  constructor(quiz) {
    this.quiz = quiz;
  }
  
  selectAnswer(answerIndex) {
    throw new Error('子类必须实现');
  }
  
  next() {
    throw new Error('子类必须实现');
  }
  
  getFeedback() {
    return null;
  }
}

// 未开始状态
class NotStartedState extends QuizState {
  selectAnswer() {
    // 未开始时不能选答案，或者自动开始
    this.quiz.setState(new AnsweringState(this.quiz));
    this.quiz.selectAnswer(answerIndex);
  }
  
  next() {
    this.quiz.setState(new AnsweringState(this.quiz));
  }
}

// 答题中状态（考试模式）
class AnsweringState extends QuizState {
  selectAnswer(answerIndex) {
    this.quiz.recordAnswer(answerIndex);
    
    if (this.quiz.isLastQuestion()) {
      this.quiz.setState(new FinishedState(this.quiz));
    } else {
      this.quiz.nextQuestion();
    }
  }
  
  next() {
    // 考试模式下，next 只是进入下一题
    if (!this.quiz.isLastQuestion()) {
      this.quiz.nextQuestion();
    } else {
      this.quiz.setState(new FinishedState(this.quiz));
    }
  }
}

// 即时反馈状态（即时模式专属）
class ImmediateFeedbackState extends QuizState {
  selectAnswer(answerIndex) {
    this.quiz.recordAnswer(answerIndex);
    const isCorrect = this.quiz.checkCurrentAnswer(answerIndex);
    this.quiz.setFeedback({ isCorrect, show: true });
    
    // 切换到等待下一题状态
    this.quiz.setState(new WaitingNextState(this.quiz));
  }
  
  next() {
    // 此状态下不能直接 next
  }
}

class WaitingNextState extends QuizState {
  selectAnswer() {
    // 不能选答案
  }
  
  next() {
    if (this.quiz.isLastQuestion()) {
      this.quiz.setState(new FinishedState(this.quiz));
    } else {
      this.quiz.nextQuestion();
      this.quiz.setState(new ImmediateFeedbackState(this.quiz));
    }
  }
}

// 已完成状态
class FinishedState extends QuizState {
  selectAnswer() {
    // 不能再选
  }
  
  next() {
    // 不能再下一题
  }
  
  getResult() {
    return this.quiz.calculateResult();
  }
}

// 答题引擎（状态机）
class QuizEngine {
  constructor(questions, config) {
    this.questions = questions;
    this.config = config;
    this.currentIndex = 0;
    this.answers = [];
    this.state = new NotStartedState(this);
  }
  
  setState(state) {
    this.state = state;
  }
  
  selectAnswer(answerIndex) {
    this.state.selectAnswer(answerIndex);
  }
  
  next() {
    this.state.next();
  }
  
  // ... 其他方法
}
```

**为什么用状态模式？**
- 答题流程的状态转换清晰
- 避免大量 `if/else` 判断当前模式
- 新增模式（如“错题重做模式”）只需新增状态类

### 2.4 工厂模式：题目组件（QuestionFactory）

**问题**：不同题型（单选、多选、判断、填空）的渲染方式和交互逻辑不同。

```javascript
// 题目组件工厂
class QuestionComponentFactory {
  static create(question, props) {
    switch (question.type) {
      case 'single':
        return <SingleChoiceQuestion key={question.id} {...props} />;
      case 'multiple':
        return <MultipleChoiceQuestion key={question.id} {...props} />;
      case 'truefalse':
        return <TrueFalseQuestion key={question.id} {...props} />;
      case 'fill':
        return <FillBlankQuestion key={question.id} {...props} />;

        return <SingleChoiceQuestion key={question.id} {...props} />;

  }
}

// 使用
function QuestionRenderer({ question, onAnswer, userAnswer }) {
  return QuestionComponentFactory.create(question, {
    question,
    onAnswer,
    userAnswer
  });
}
```

**为什么用工厂模式？**
- 新增题型不影响现有代码
- 创建逻辑集中管理
- 组件复用性高

### 2.5 建造者模式：题库构建

**问题**：解析结果到题库对象的构建过程复杂，需要校验、补充默认值、计算统计信息。

```javascript
class QuestionBankBuilder {
  constructor() {
    this.reset();
  }
  
  reset() {
    this.bank = {
      id: null,
      name: '',
      description: '',
      category: '',
      questions: [],
      questionCount: 0,
      createdAt: null,
      updatedAt: null
    };
  }
  
  setId(id) {
    this.bank.id = id || crypto.randomUUID();
    return this;
  }
  
  setName(name) {
    this.bank.name = name || '未命名题库';
    return this;
  }
  
  setDescription(desc) {
    this.bank.description = desc || '';
    return this;
  }
  
  setCategory(category) {
    this.bank.category = category || '未分类';
    return this;
  }
  
  addQuestion(question) {
    // 校验必要字段
    if (!question.text) {
      throw new Error('题目文本不能为空');
    }
    if (!question.correct && question.correct !== 0) {
      throw new Error('正确答案不能为空');
    }
    
    // 补充默认值
    const normalized = {
      id: question.id || `q${this.bank.questions.length + 1}`,
      text: question.text,
      options: question.options || ['A', 'B', 'C', 'D'],
      correct: question.correct,
      explanation: question.explanation || '暂无解析'
    };
    
    this.bank.questions.push(normalized);
    return this;
  }
  
  addQuestions(questions) {
    questions.forEach(q => this.addQuestion(q));
    return this;
  }
  
  build() {
    this.bank.questionCount = this.bank.questions.length;
    this.bank.createdAt = this.bank.createdAt || new Date().toISOString();
    this.bank.updatedAt = new Date().toISOString();
    
    const result = { ...this.bank };
    this.reset();
    return result;
  }
}

// 使用
const builder = new QuestionBankBuilder();
const bank = builder
  .setId('bank-001')
  .setName('JavaScript 基础测验')
  .setCategory('JavaScript')
  .addQuestion({
    text: '以下哪个是 JavaScript 的变量声明关键字？',
    options: ['var', 'const', 'let', '以上都是'],
    correct: 3,
    explanation: 'var/let/const 都是 JS 声明变量的关键字'
  })
  .addQuestion({
    text: '以下哪个是 React 的 Hook？',
    options: ['useState', 'useEffect', 'useContext', '以上都是'],
    correct: 3
  })
  .build();
```

**为什么用建造者模式？**
- 创建过程步骤清晰
- 可以校验和补充默认值
- 易扩展（如增加封面图、标签等字段）

```javascript
// patterns/QuestionFactory.js

class QuestionFactory {
  static create(type, rawData) {
    const creators = {
      single_choice: SingleChoiceQuestion,
      multiple_choice: MultipleChoiceQuestion,
      true_false: TrueFalseQuestion
    };
    
    const Creator = creators[type];
    if (!Creator) throw new Error(`未知题型: ${type}`);
    
    return new Creator(rawData);
  }
}

class BaseQuestion {
  constructor(data) {
    this.id = data.id || generateUUID();
    this.content = data.content;
    this.explanation = data.explanation || '';
    this.difficulty = data.difficulty || 1;
    this.tags = data.tags || [];
  }
  
  validate() {
    throw new Error('子类必须实现validate');
  }
}

class SingleChoiceQuestion extends BaseQuestion {
  constructor(data) {
    super(data);
    this.type = 'single_choice';
    this.options = data.options || [];
    this.correctIndex = data.correctIndex ?? 0;
  }
  
  validate() {
    return this.options.length >= 2 && 
           this.correctIndex >= 0 && 
           this.correctIndex < this.options.length;
  }
  
  checkAnswer(userAnswer) {
    return userAnswer === this.correctIndex;
  }
}

class MultipleChoiceQuestion extends BaseQuestion {
  constructor(data) {
    super(data);
    this.type = 'multiple_choice';
    this.options = data.options || [];
    this.correctIndex = Array.isArray(data.correctIndex) 
      ? data.correctIndex 
      : [data.correctIndex];
  }
  
  validate() {
    return this.options.length >= 2 &&
           this.correctIndex.every(i => i >= 0 && i < this.options.length);
  }
  
  checkAnswer(userAnswer) {
    const user = [...userAnswer].sort();
    const correct = [...this.correctIndex].sort();
    return user.length === correct.length && 
           user.every((v, i) => v === correct[i]);
  }
}

class TrueFalseQuestion extends BaseQuestion {
  constructor(data) {
    super(data);
    this.type = 'true_false';
    this.options = [
      { id: 0, text: '正确' },
      { id: 1, text: '错误' }
    ];
    this.correctIndex = data.correctIndex ?? 0; // 0=正确, 1=错误
  }
  
  validate() {
    return this.correctIndex === 0 || this.correctIndex === 1;
  }
  
  checkAnswer(userAnswer) {
    return userAnswer === this.correctIndex;
  }
}
```

### 2.2 策略模式：组卷算法 + 计分 + 显示模式

```javascript
// patterns/StrategyPattern.js

// ==================== 组卷策略 ====================
class QuizStrategy {
  generate(pool, count) {
    throw new Error('子类必须实现generate');
  }
}

class RandomStrategy extends QuizStrategy {
  generate(pool, count) {
    const shuffled = shuffle([...pool]);
    return shuffled.slice(0, Math.min(count, shuffled.length));
  }
}

class DifficultyWeightedStrategy extends QuizStrategy {
  constructor(difficultyDistribution = { 1: 0.3, 2: 0.3, 3: 0.2, 4: 0.1, 5: 0.1 }) {
    super();
    this.distribution = difficultyDistribution;
  }
  
  generate(pool, count) {
    // 按难度分布加权抽样
    const result = [];
    const grouped = groupBy(pool, 'difficulty');
    
    Object.entries(this.distribution).forEach(([diff, ratio]) => {
      const need = Math.floor(count * ratio);
      const available = grouped[diff] || [];
      result.push(...shuffle(available).slice(0, need));
    });
    
    // 补足剩余
    const remaining = count - result.length;
    if (remaining > 0) {
      const rest = pool.filter(q => !result.includes(q));
      result.push(...shuffle(rest).slice(0, remaining));
    }
    
    return shuffle(result);
  }
}

class WrongQuestionPriorityStrategy extends QuizStrategy {
  constructor(wrongQuestionIds) {
    super();
    this.wrongIds = new Set(wrongQuestionIds);
  }
  
  generate(pool, count) {
    const wrongQuestions = pool.filter(q => this.wrongIds.has(q.id));
    const others = pool.filter(q => !this.wrongIds.has(q.id));
    
    // 错题优先，但不超过总量的60%
    const wrongCount = Math.min(Math.floor(count * 0.6), wrongQuestions.length);
    const otherCount = count - wrongCount;
    
    return [
      ...shuffle(wrongQuestions).slice(0, wrongCount),
      ...shuffle(others).slice(0, otherCount)
    ];
  }
}

// ==================== 计分策略 ====================
class ScoreStrategy {
  calculate(answers, totalQuestions) {
    throw new Error('子类必须实现calculate');
  }
}

class StandardScoreStrategy extends ScoreStrategy {
  calculate(answers, totalQuestions) {
    const correct = answers.filter(a => a.isCorrect).length;
    return {
      score: Math.round((correct / totalQuestions) * 100),
      correctCount: correct,
      totalCount: totalQuestions,
      pass: correct / totalQuestions >= 0.6
    };
  }
}

class GameScoreStrategy extends ScoreStrategy {
  // 游戏模式：连续答对有连击加分
  calculate(answers, totalQuestions) {
    let baseScore = 0;
    let streak = 0;
    let maxStreak = 0;
    let bonus = 0;
    
    answers.forEach(a => {
      if (a.isCorrect) {
        streak++;
        maxStreak = Math.max(maxStreak, streak);
        baseScore += 10;
        bonus += (streak - 1) * 2; // 连击奖励
      } else {
        streak = 0;
      }
    });
    
    const totalScore = baseScore + bonus;
    const maxPossible = totalQuestions * 10 + (totalQuestions - 1) * totalQuestions; // 理论最高分
    
    return {
      score: Math.round((totalScore / maxPossible) * 100),
      baseScore,
      bonus,
      maxStreak,
      correctCount: answers.filter(a => a.isCorrect).length,
      totalCount: totalQuestions
    };
  }
}
```

```javascript
class QuizState {
  constructor(context) {
    this.context = context;
  }
  
  enter() {}
  exit() {}
  canSelectOption() { return false; }
  canSubmit() { return false; }
  canNavigate() { return false; }
  canShowExplanation() { return false; }
}

class IdleState extends QuizState {
  enter() {
    console.log('测验未开始');
  }
  
  canNavigate() { return true; } // 可以选题库/设置
}

class PlayingState extends QuizState {
  enter() {
    this.context.startTimer();
  }
  
  canSelectOption() { return true; }
  canNavigate() { return true; } // 上一题/下一题
  
  selectOption(questionIndex, optionIndex) {
    this.context.answers[questionIndex] = {
      ...this.context.answers[questionIndex],
      userAnswer: optionIndex,
      answeredAt: Date.now()
    };
    
    // 游戏模式：立即判题
    if (this.context.displayMode.shouldShowAnswerImmediately()) {
      this.context.judgeQuestion(questionIndex);
    }
  }
  
  canShowExplanation() {
    return this.context.displayMode.shouldShowAnswerImmediately() &&
           this.context.answers[this.context.currentQuestion]?.userAnswer !== undefined;
  }
}

class SubmittedState extends QuizState {
  enter() {
    this.context.stopTimer();
    this.context.calculateFinalScore();
  }
  
  canShowExplanation() { return true; } // 所有题都可以看解析
  canNavigate() { return true; } // 回顾模式自由跳转
}

class ReviewState extends QuizState {
  // 历史记录回顾，不可修改答案
  canSelectOption() { return false; }
  canShowExplanation() { return true; }
  canNavigate() { return true; }
}

// 状态机上下文
class QuizSession {
  constructor(config) {
    this.config = config;
    this.state = new IdleState(this);
    this.questions = [];
    this.answers = [];
    this.currentQuestion = 0;
    this.startTime = null;
    this.duration = 0;
    this.displayMode = config.displayMode;
  }
  
  setState(newState) {
    this.state.exit();
    this.state = newState;
    this.state.enter();
  }
  
  start(questions) {
    this.questions = questions;
    this.answers = questions.map(q => ({
      questionId: q.id,
      userAnswer: null,
      isCorrect: null,
      timeSpent: 0
    }));
    this.setState(new PlayingState(this));
  }
  
  selectOption(optionIndex) {
    if (!this.state.canSelectOption()) return;
    this.state.selectOption(this.currentQuestion, optionIndex);
  }
  
  submit() {
    if (!this.state.canSubmit()) {
      // 自动提交未答题目
      this.answers.forEach((a, i) => {
        if (a.userAnswer === null) {
          a.userAnswer = -1; // 标记为未答
          a.isCorrect = false;
        }
      });
    }
    this.setState(new SubmittedState(this));
  }
  
  judgeQuestion(index) {
    const q = this.questions[index];
    const a = this.answers[index];
    const question = QuestionFactory.create(q.type, q);
    a.isCorrect = question.checkAnswer(a.userAnswer);
    a.correctIndex = q.displayCorrectIndex; // 记录当时显示的正确答案位置
  }
  
  calculateFinalScore() {
    // 对未即时判分的题目补判
    this.answers.forEach((a, i) => {
      if (a.isCorrect === null) {
        this.judgeQuestion(i);
      }
    });
    
    const scoreResult = this.config.scoreStrategy.calculate(
      this.answers, 
      this.questions.length
    );
    
    this.result = scoreResult;
    return scoreResult;
  }
}
```

```javascript
class HybridStorageAdapter extends StorageAdapter {
  constructor(localAdapter, cloudAdapter) {
    super();
    this.local = localAdapter;
    this.cloud = cloudAdapter;
    this.isOnline = false;
    this.user = null;
  }
  
  async login(credentials) {

    const { data, error } = await this.cloud.supabase.auth.signInWithPassword(credentials);
    if (error) throw error;
    this.user = data.user;
    this.isOnline = true;
    return data.user;
  }
  
  async getBanks() {
    // 本地优先，云端补充
    const localBanks = await this.local.getBanks();
    
    if (this.isOnline && this.user) {
      try {
        const cloudBanks = await this.cloud.getBanks();
        // 合并，云端优先（更新）
        const merged = this.mergeBanks(localBanks, cloudBanks);
        return merged;
      } catch (e) {
        console.warn('云端获取失败，使用本地数据', e);
        return localBanks;
      }
    }
    
    return localBanks;
  }
  
  async saveBank(bank, questions) {
    // 总是先存本地
    const localId = await this.local.saveBank(bank, questions);
    
    if (this.isOnline && this.user) {
      try {
        const cloudId = await this.cloud.saveBank(bank, questions);
        // 更新本地记录的云端ID
        await this.local.updateBankSyncStatus(localId, { cloudId, isSynced: true });
      } catch (e) {
        console.warn('云端保存失败，标记为待同步', e);
        await this.local.updateBankSyncStatus(localId, { isSynced: false });
      }
    }
    
    return localId;
  }
  
  mergeBanks(local, cloud) {
    const map = new Map();
    
    // 本地优先加入
    local.forEach(b => map.set(b.id, { ...b, source: 'local' }));
    
    // 云端覆盖或补充
    cloud.forEach(b => {
      const existing = map.get(b.local_id);
      if (existing) {
        // 合并：云端数据更新，但保留本地ID
        map.set(existing.id, { ...b, localId: existing.id, source: 'merged' });
      } else {
        map.set(b.id, { ...b, source: 'cloud' });
      }
    });
    
    return Array.from(map.values());
  }
}
```

# 「小测」MVP 版设计模式专项补充方案

## 一、设计模式选型核心原则



1. **轻量化优先**：拒绝过度设计，仅选用解决核心问题的模式，避免增加开发复杂度；

2. **适配单人开发**：模式逻辑简单易懂，AI 可快速生成对应代码，后续维护成本低；

3. **扩展性预留**：兼顾未来功能迭代（如新增 Word 解析、多题型支持），无需重构核心逻辑；

4. **贴合技术栈**：所有模式均适配 UniApp (Vue3)+FastAPI 技术栈，无框架冲突。

## 二、核心设计模式详解（含应用场景 + 代码示例思路）

### 1. 策略模式（核心强化）

#### （1）原有应用场景



* TXT 解析策略 / MD 解析策略

* 考试型计分策略 / 游戏型计分策略

#### （2）新增扩展场景



* 本地存储策略 / 云端存储策略（双存储模式核心）

* 即时解析展示策略 / 测后解析展示策略（双展示模式核心）

#### （3）实现逻辑（以存储策略为例）



```
// 1. 定义策略接口（统一方法名）

class StorageStrategy {

&#x20; getQuestion(id) {} // 获取题目

&#x20; saveQuestion(question) {} // 保存题目

&#x20; syncData() {} // 同步数据（本地策略可空实现）

}

// 2. 实现本地存储策略

class LocalStorageStrategy extends StorageStrategy {

&#x20; getQuestion(id) {

&#x20;   return indexedDB.get('questions', id); // 操作本地IndexedDB

&#x20; }

&#x20; saveQuestion(question) {

&#x20;   return indexedDB.put('questions', question);

&#x20; }

&#x20; syncData() {

&#x20;   console.log('本地模式无需同步');

&#x20; }

}

// 3. 实现云端存储策略

class CloudStorageStrategy extends StorageStrategy {

&#x20; getQuestion(id) {

&#x20;   return uni.request({ url: \`/api/question/\${id}\` }); // 调用后端接口

&#x20; }

&#x20; saveQuestion(question) {

&#x20;   return uni.request({ url: '/api/question', method: 'POST', data: question });

&#x20; }

&#x20; syncData() {

&#x20;   return uni.request({ url: '/api/sync' }); // 云端同步逻辑

&#x20; }

}

// 4. 策略上下文（统一调用入口）

class StorageContext {

&#x20; constructor(strategy) {

&#x20;   this.strategy = strategy; // 传入具体策略

&#x20; }

&#x20; setStrategy(strategy) {

&#x20;   this.strategy = strategy; // 支持动态切换策略

&#x20; }

&#x20; getQuestion(id) {

&#x20;   return this.strategy.getQuestion(id); // 委托给策略执行

&#x20; }

}

// 5. 调用示例（前端使用）

const localStrategy = new LocalStorageStrategy();

const cloudStrategy = new CloudStorageStrategy();

const storage = new StorageContext(localStrategy); // 默认本地模式

// 切换云端模式

storage.setStrategy(cloudStrategy);

storage.getQuestion('123'); // 自动调用云端接口
```

#### （4）核心价值



* 多种模式逻辑分离，代码结构清晰（如存储逻辑不与业务逻辑混杂）；

* 新增模式（如未来新增「私有化部署存储」），无需修改原有代码，直接新增策略类；

* 前端可根据用户配置动态切换策略（如登录后切换云端存储）。

### 2. 工厂模式（扩展应用）

#### （1）应用场景



* 题目工厂：根据题型（单选 / 判断）生成统一格式题目；

* 试卷工厂：根据组卷配置（标签 / 题量 / 模式）生成试卷实例；

* 策略工厂：根据用户配置（存储模式 / 展示模式）生成对应策略实例。

#### （2）实现逻辑（以策略工厂为例）



```
class StrategyFactory {

&#x20; // 根据配置生成存储策略

&#x20; createStorageStrategy(storageType) {

&#x20;   if (storageType === 'local') {

&#x20;     return new LocalStorageStrategy();

&#x20;   } else if (storageType === 'cloud') {

&#x20;     return new CloudStorageStrategy();

&#x20;   }

&#x20;   throw new Error('不支持的存储模式');

&#x20; }

&#x20; // 根据配置生成展示策略

&#x20; createShowStrategy(showMode) {

&#x20;   if (showMode === 'instant') {

&#x20;     return new InstantShowStrategy();

&#x20;   } else if (showMode === 'after') {

&#x20;     return new AfterShowStrategy();

&#x20;   }

&#x20;   throw new Error('不支持的展示模式');

&#x20; }

}

// 调用示例

const factory = new StrategyFactory();

const storageStrategy = factory.createStorageStrategy('local');

const showStrategy = factory.createShowStrategy('instant');
```

#### （3）核心价值



* 封装策略创建逻辑，避免在业务代码中写大量`if-else`判断；

* 统一策略创建入口，后续修改策略实现时，仅需修改工厂类，无需改动业务代码；

* 降低策略类与业务代码的耦合度，AI 生成代码时可单独生成工厂和策略。

### 3. 单例模式（精准应用）

#### （1）应用场景



* 存储管理器：全局唯一的存储操作入口（避免重复创建 IndexedDB 连接或接口请求实例）；

* 解析管理器：全局唯一的 TXT/MD 解析入口（统一解析规则，避免重复初始化）；

* 配置管理器：全局唯一的用户配置存储（如默认存储模式、常用组卷配置）。

#### （2）实现逻辑（以存储管理器为例）



```
class StorageManager {

&#x20; constructor() {

&#x20;   if (StorageManager.instance) {

&#x20;     return StorageManager.instance; // 已存在则返回实例

&#x20;   }

&#x20;   this.strategy = new LocalStorageStrategy(); // 默认策略

&#x20;   StorageManager.instance = this;

&#x20; }

&#x20; static getInstance() {

&#x20;   if (!StorageManager.instance) {

&#x20;     new StorageManager();

&#x20;   }

&#x20;   return StorageManager.instance;

&#x20; }

&#x20; setStrategy(strategy) {

&#x20;   this.strategy = strategy;

&#x20; }

&#x20; // 代理策略方法

&#x20; getQuestion(id) {

&#x20;   return this.strategy.getQuestion(id);

&#x20; }

}

// 调用示例（全局唯一实例）

const storageManager = StorageManager.getInstance();

storageManager.getQuestion('123');
```

#### （3）核心价值



* 避免重复创建资源密集型实例（如 IndexedDB 连接、解析正则对象），提升性能；

* 全局统一操作入口，避免数据不一致（如同一时间既有本地存储又有云端存储操作）；

* 简化全局状态管理，无需通过 Vuex 传递存储实例，直接调用单例即可。

### 4. 适配器模式（新增强化）

#### （1）应用场景



* 题库格式适配器：将用户上传的杂乱 TXT/MD 文本 → 标准题目 JSON 格式（核心适配场景）；

* 后端接口适配器：将云端接口返回数据 → 与本地 IndexedDB 一致的数据格式（避免双存储数据结构差异）；

* 第三方组件适配器：将 UniApp 内置组件 → 统一的自定义组件接口（如单选按钮、解析展示组件）。

#### （2）实现逻辑（以题库格式适配器为例）



```
// 1. 定义目标接口（标准题目格式）

class StandardQuestion {

&#x20; constructor({ id, title, type, options, answer, analysis, tags }) {

&#x20;   this.id = id;

&#x20;   this.title = title;

&#x20;   this.type = type;

&#x20;   this.options = options;

&#x20;   this.answer = answer;

&#x20;   this.analysis = analysis;

&#x20;   this.tags = tags;

&#x20; }

}

// 2. 实现TXT格式适配器

class TxtQuestionAdapter {

&#x20; adapt(rawText) {

&#x20;   // 第一步：拆分题目块（按---分割）

&#x20;   const questionBlocks = rawText.split('---').filter(block => block.trim());

&#x20;   return questionBlocks.map(block => {

&#x20;     // 第二步：提取题干（首行非选项/答案/解析）

&#x20;     const lines = block.trim().split('\n').map(line => line.trim());

&#x20;     const title = lines.find(line => !/^\[A-D对错]\\.|【答案】|【解析】/.test(line));

&#x20;    &#x20;

&#x20;     // 第三步：提取选项

&#x20;     const options = lines

&#x20;       .filter(line => /^\[A-D]\\./.test(line))

&#x20;       .map(line => ({

&#x20;         label: line.slice(0, 1),

&#x20;         content: line.slice(2)

&#x20;       }));

&#x20;     // 第四步：提取答案和解析（适配宽松格式）

&#x20;     const answerLine = lines.find(line => line.includes('【答案】')) || '';

&#x20;     const answer = answerLine.replace('【答案】', '').trim();

&#x20;     const analysisLine = lines.find(line => line.includes('【解析】')) || '';

&#x20;     const analysis = analysisLine.replace('【解析】', '').trim();

&#x20;     // 第五步：返回标准格式

&#x20;     return new StandardQuestion({

&#x20;       id: crypto.randomUUID(), // 生成UUID

&#x20;       title,

&#x20;       type: options.length > 2 ? 1 : 2, // 单选/判断

&#x20;       options,

&#x20;       answer,

&#x20;       analysis,

&#x20;       tags: \['用户导入']

&#x20;     });

&#x20;   });

&#x20; }

}

// 3. 调用示例

const txtAdapter = new TxtQuestionAdapter();

const rawTxt = \`题干：JS中let和const的区别？

A. let可修改，const不可修改

B. let不可修改，const可修改

C. 两者无区别

D. 仅let支持全局声明

【答案】A

【解析】const声明的变量不可修改，let声明的变量可修改。

\---\`;

const standardQuestions = txtAdapter.adapt(rawTxt); // 输出标准题目格式
```

#### （3）核心价值



* 屏蔽用户输入格式的差异性，前端业务代码仅需处理标准格式，降低逻辑复杂度；

* 后续新增解析格式（如 Word），仅需新增适配器，无需修改业务逻辑；

* 统一数据格式，确保本地存储和云端存储的数据结构完全一致，同步时无冲突。

### 5. 观察者模式（新增适配）

#### （1）应用场景



* 数据同步观察者：本地数据修改后，自动通知云端同步（如新增题目后触发云端备份）；

* 测试状态观察者：答题状态变化时（如提交试卷、标记错题），自动更新测试记录和错题本；

* 界面更新观察者：存储模式切换后（本地→云端），自动刷新界面数据。

#### （2）实现逻辑（以测试状态观察者为例）



```
// 1. 定义被观察者（答题状态）

class ExamSubject {

&#x20; constructor() {

&#x20;   this.observers = \[]; // 观察者列表

&#x20; }

&#x20; // 注册观察者

&#x20; addObserver(observer) {

&#x20;   this.observers.push(observer);

&#x20; }

&#x20; // 移除观察者

&#x20; removeObserver(observer) {

&#x20;   this.observers = this.observers.filter(obs => obs !== observer);

&#x20; }

&#x20; // 通知所有观察者

&#x20; notify(state) {

&#x20;   this.observers.forEach(observer => observer.update(state));

&#x20; }

&#x20; // 答题状态变化（如提交试卷）

&#x20; submitExam(examResult) {

&#x20;   this.notify({ type: 'submit', data: examResult }); // 通知观察者

&#x20; }

}

// 2. 实现观察者1：更新测试记录

class RecordObserver {

&#x20; update(state) {

&#x20;   if (state.type === 'submit') {

&#x20;     const { data } = state;

&#x20;     // 保存测试记录到本地/云端

&#x20;     StorageManager.getInstance().saveQuestion('exam\_records', data);

&#x20;   }

&#x20; }

}

// 3. 实现观察者2：更新错题本

class WrongQuestionObserver {

&#x20; update(state) {

&#x20;   if (state.type === 'submit') {

&#x20;     const { data: { wrongQuestions } } = state;

&#x20;     // 批量添加错题到错题本

&#x20;     wrongQuestions.forEach(questionId => {

&#x20;       StorageManager.getInstance().saveQuestion('wrong\_questions', {

&#x20;         question\_id: questionId,

&#x20;         wrong\_times: 1,

&#x20;         last\_wrong\_time: new Date().toISOString()

&#x20;       });

&#x20;     });

&#x20;   }

&#x20; }

}

// 4. 调用示例

const examSubject = new ExamSubject();

const recordObserver = new RecordObserver();

const wrongObserver = new WrongQuestionObserver();

// 注册观察者

examSubject.addObserver(recordObserver);

examSubject.addObserver(wrongObserver);

// 提交试卷时自动触发所有观察者

examSubject.submitExam({

&#x20; paper\_id: 'xxx',

&#x20; correct\_num: 8,

&#x20; wrong\_num: 2,

&#x20; wrongQuestions: \['q1', 'q2'],

&#x20; score: 7,

&#x20; cost\_time: 300

});
```

#### （3）核心价值



* 解耦状态变化和后续操作（如提交试卷后，无需手动调用「保存记录」和「添加错题」）；

* 新增后续操作（如提交后弹出分享弹窗），仅需新增观察者，无需修改提交逻辑；

* 支持动态添加 / 移除观察者，灵活控制业务流程（如离线模式下移除云端同步观察者）。

## 三、设计模式应用全景图（MVP 阶段）



| 设计模式   | 核心解决问题                                | 应用模块                     | 代码复用度 | 扩展价值 |
| ---------- | ------------------------------------------- | ---------------------------- | ---------- | -------- |
| 策略模式   | 多模式（存储 / 展示 / 计分 / 解析）逻辑分离 | 存储模块、答题模块、组卷模块 | 高         | 高       |
| 工厂模式   | 统一实例创建（策略 / 题目 / 试卷）          | 组卷模块、解析模块           | 中         | 高       |
| 单例模式   | 全局唯一资源（存储 / 解析 / 配置）管理      | 存储模块、配置模块           | 高         | 中       |
| 适配器模式 | 异构数据 / 组件格式统一                     | 解析模块、同步模块           | 高         | 高       |
| 观察者模式 | 状态变化自动触发后续操作                    | 答题模块、记录模块           | 中         | 高       |

## 四、落地建议（单人开发适配）



1. **优先实现核心模式**：策略模式（存储 + 展示 + 计分）→ 适配器模式（解析）→ 单例模式（存储管理），这三个模式覆盖 80% 核心业务；

2. **简化模式实现**：无需严格遵循设计模式规范（如观察者模式可省略抽象类，直接用回调函数），以「能用、好写」为原则；

3. **AI 生成辅助**：将每个模式的核心逻辑（如策略模式的接口和实现类）单独告诉 AI，让 AI 生成基础代码，你仅需微调适配业务；

4. **避免过度设计**：MVP 阶段无需新增更多模式（如装饰器、代理模式），后续迭代时根据需求补充。

## 五、总结

本次补充的设计模式方案，完全围绕你的 MVP 核心需求展开，既解决了「双模式、双存储、双解析」的核心问题，又兼顾了单人开发的效率和未来的扩展性。所有模式均提供了具体的代码实现思路，可直接对接 AI 生成代码，无需你从零编写复杂逻辑。

实际开发时，建议先基于「策略模式 + 适配器模式 + 单例模式」搭建核心框架，再逐步完善其他模式，确保开发过程顺畅、代码结构清晰。

二、本项目「必用」的 4 种设计模式（按重要性排序）

① Strategy 策略模式 —— ⭐⭐⭐⭐⭐

用途：解决你刚加的 “考试型 / 游戏型计分”

为什么用

• 两种计分规则：

  • 考试型：百分比

  • 游戏型：HP / 连击 / 惩罚

• 未来还可能加：

  • 竞赛模式

  • 错题加权模式

结构

class ScoringStrategy(ABC):
    @abstractmethod
    def calculate(self, answers):
        pass

class ExamScoring(ScoringStrategy):
    ...

class GameScoring(ScoringStrategy):
    ...


使用处

scorer = GameScoring(rules)
score = scorer.calculate(user_answers)


✅ 这是你这个项目的“灵魂模式”之一

② Factory Method 工厂模式 —— ⭐⭐⭐⭐

用途：题库解析（TXT / MD / 未来 Word）

为什么用

• 不同文件格式 → 不同解析逻辑

• Controller 不应该关心“怎么解析”

结构

class Parser(ABC):
    @abstractmethod
    def parse(self, content):
        pass

class TxtParser(Parser):
    ...

class MdParser(Parser):
    ...


工厂

def get_parser(source_type: str) -> Parser:
    if source_type == "txt":
        return TxtParser()
    if source_type == "md":
        return MdParser()


✅ 你之后加 PDF / Word，不改业务代码

③ Repository（DAO）模式 —— ⭐⭐⭐⭐

用途：隔离数据库细节

为什么用

• 防止 SQL 散落在接口里

• 方便测试、替换 ORM、写单元测试

示例

class QuestionRepository:
    def save_many(self, questions):
        ...

    def find_by_bank(self, bank_id):
        ...


✅ 你已经有系统经验，会非常认同这一层

④ State（或前端状态机）模式 —— ⭐⭐⭐

用途：前端答题页的“即时 / 考后”反馈

为什么用

• 答题页有很多状态：

  • 未作答

  • 已作答（即时反馈）

  • 已提交

• if-else 会爆炸

前端（Vue 伪代码）

const states = {
  idle: { submit() { ... } },
  answered: { next() { ... } },
  finished: { restart() { ... } }
}


✅ 特别适合你这种“状态清晰、规则明确”的场景
