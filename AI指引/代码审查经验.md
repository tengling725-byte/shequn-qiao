# 代码审查经验

## 经验一：`await` 优先级低于成员访问运算符

JavaScript 中 `await` 运算符优先级（17）低于 `.` 成员访问（18）。`await fn().method()` 等价于 `await (fn().method())`，而不是 `(await fn()).method()`。

当 `fn()` 返回 Promise 时，在 Promise 上调用 `.filter()` / `.map()` / `.find()` 会抛出 `TypeError: xxx.filter is not a function`。

**排查方法**：搜索 `await\s+\w+\(\)\.` 模式，检查是否存在该陷阱。

**正确写法**：`(await fn()).method()` 或分两行先 resolve。

## 经验二：任何接收外部路径输入的文件服务，必须做路径边界校验

直接将 `req.url` 拼接到文件系统路径（如 `'.' + req.url`）会引入路径遍历漏洞。攻击者可以通过 `../` 读取任意文件。这不是某个框架的问题，而是所有自建静态文件服务的通病。

**防御方式**：
- 使用 `path.resolve` + 前缀比对（确保解析后路径仍在允许目录内）
- 或使用成熟的静态文件中间件（express.static、serve-static 等）

**验证方式**：`curl --path-as-is 'http://localhost:PORT/../secret.txt'`

## 经验三：密钥不落盘到版本控制

配置文件（toml/yaml/json/.env）中硬编码的密钥，一旦提交就会被永久记录在 Git 历史中。即使从当前版本删除，`git log --all --full-history` 仍可还原。

**原则**：
- 本地开发密钥放 `.env`，且确保 `.gitignore` 包含它
- 生产环境密钥走平台 Secret 管理（如 `wrangler secret put`、GitHub Secrets、Vercel Environment Variables）
- 模板文件（`.env.example`）只放变量名，不放值

## 经验四：声明的依赖必须被使用

`package.json` 中未引用的依赖增加安装时间、node_modules 体积和安全审计范围。引入新依赖时确认它确实被 `require` 或 `import`。

**排查**：`npx depcheck` 可自动扫描未使用依赖。
